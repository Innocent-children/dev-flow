# 自定义宠物形象

[中文](appearance-packs.md) | [English](appearance-packs_en.md)

## 问题

当前应用固定使用内置形象。用户希望制作自己的形象，或直接使用已有 Codex 宠物，无需修改、重新编译 Dev Flow。

## 当前做法

开发者修改构建素材后重打包。播放器已将任务状态与图片帧分开，但用户没有导入和切换入口。

## 可用数据

应用已有五类展示状态、PNG 帧播放器和用户偏好目录。Codex 本地包包含 `pet.json` 和 PNG/WebP 精灵图；
官方当前接受 `spriteVersionNumber` 为 1 或 2。此次按用户追加要求兼容这两种本地素材格式。

## 行为规则

- 菜单增加“选择形象”，包含内置形象、已导入形象和“导入形象…”；导入对象为本地文件夹。
- Dev Flow 自有包的 `pet.json` 包含 `id`、`name` 和可选的 `image`。有 `image` 时将一张 PNG 用于全部状态；
  无 `image` 时读取同目录的 `animations.json` 和 `Assets/`，复用五类动作清单。每类允许单帧。
- 动作可选 `frame_durations_ms`，与帧列表等长；未提供时使用 `fps`。导入 Codex 时保留原有逐帧时长。
- Codex 包读取 `id`、`displayName`、`spritesheetPath`，省略版本按 1 处理。只接受标准 8 列图集：
  版本 1 为 1536×1872，版本 2 为 1536×2288，单格均为 192×208。
- Codex 映射：idle→待机，running→普通阶段，waiting→受阻，jumping→完成，failed→未连接。
  导入时拆成 PNG 帧并保存为统一动作清单；任务语义、气泡和跳转由 Dev Flow 决定。
- 用户包复制到 `productRoot/pet/appearances/<id>`，仅保留描述与引用的图片；重导入同 ID 更新该形象。
  验证失败保留原有文件、选择和画面。导入完成即选中；内置形象始终可选。
- 偏好增加 `selected_appearance`；重启恢复选择，升级保留目录，已确认 factory-reset 按现有 pet 目录规则清理。
  保存的形象丢失或损坏时明确提示并使用内置形象。
- 切换释放旧图片与动画，直接展示新形象的当前状态，不重播旧完成提示，也不改变关注任务。
- 外部文件仅接受相对路径及普通图片文件，拒绝符号链接、目录逃逸和超出资源上限的包。默认形象仍随应用分发。

## 预期结果

用户从菜单导入一个形象文件夹并立即使用，之后可在菜单切换；不需要 Swift 或重新安装 Dev Flow。

## 风险与影响

错误素材可能导致缺帧、过多内存占用或读取目录外文件。导入前检查引用、图像解码、尺寸与数量，
验证完成后替换目录。任务读取和 Core 状态保持原职责，外部包不含执行逻辑。

## 验收方式

只运行形象导入与播放的定向检查：静态/动画包、Codex 两种图集、同 ID 更新、坏包保留原状、选择保存、
切换取消旧动画。可用时从最终本地安装包检查菜单导入、切换和重启恢复。未运行的原生步骤如实记录。

## 非目标

在线商店、网络下载、素材制作器、脚本插件、Codex 任务控制、追视或行走行为复刻、Core/MCP 修改和正式发布。
