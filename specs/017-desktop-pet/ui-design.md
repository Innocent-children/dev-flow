# 桌面宠物界面与动画规格

[中文](ui-design.md) | [English](ui-design_en.md)

宠物以精美的原创角色呈现 Dev Flow 任务状态。角色应在小尺寸下有清晰轮廓、自然表情和完整动作，
常驻信息清楚且克制，用户操作时得到轻巧的反馈。本规格保留[方案](plan.md)的视觉参考；已有程序化素材可用于本地功能包，视觉精修不属于当前完成条件。

## 角色与视觉方向

当前功能开发沿用现有素材，也允许使用简单静态形状。用户已将下文的形象精修、动作流畅度和视觉
检查从本次完成条件中移出；文字、点击、拖动、任务选择、可见性和动画开关继续按功能要求实现。

采用柔和立体感的原创小精灵形象：圆润体块、简洁五官、可辨识的头部与肢体，以及呼应 Dev Flow 流线
标记的造型细节。角色具备独立轮廓，不直接将产品图标放大后加眼睛，也不套用其他产品的现成吉祥物。
角色定稿先完成正面、四分之三视角及关键表情，统一身体比例、五官位置、光源和材质，再制作动作。

色彩参考现有 [Dev Flow 图标](../../packages/webui/src/assets/dev-flow-app-icon-light.svg)：
蓝色 `#387FFB` 到紫色 `#7163F7`，配合柔和的浅色高光与中性色轮廓。保留角色在浅色、深色和复杂
桌面背景上的可读性，阴影贴合角色姿态，避免厚重外发光或大面积背景底板。

正式交付包括角色原稿、五类完整动画及必要静态姿态。占位图、整张图片的上下平移或统一缩放，
不能替代角色各部位的动作设计。脸、身体、肢体与装饰的运动应有合理先后和重心变化。

## 桌面布局

默认角色显示框为 `144 × 144 pt`；在 `96 / 144 / 192 pt` 下完成清晰度检查。
这些尺寸是制作和检查尺寸，不增加用户缩放设置。默认气泡宽度约 `220 pt`，由内容和系统字体约束
最终排版；气泡位于角色上方，整体保持在屏幕可见工作区内。

常驻气泡两行：

| 区域 | 内容与排版 |
| --- | --- |
| 第一行 | 任务简称，单行省略；无选择显示“选择一个任务” |
| 第二行 | 当前阶段或连接结果，必要时附加简短的只读/归档标记 |
| 悬停展开 | 可换行的任务摘要、“任务更新于”、“最近同步”和阻塞原因；保留行距并限制最大高度 |
| 任务选择面板 | 任务摘要、来源 Host、阶段、仓库提示；当前项有选中标记，底部按需加载下一页 |

使用系统字体；建议任务名 `13 pt`、阶段 `12 pt`，展开正文至少 `12 pt`。角色与气泡之间保持
约 `8 pt` 间距。中文、英文、长任务名和长路径都需实测，不能依靠缩小全部文字塞入固定框。

首次将宠物放在主屏右下方可见区域。拖动后记住位置；显示器移除或布局变化后，将整体移回仍可见的
工作区。窗口边界围绕角色和实际气泡内容，不创建覆盖整个屏幕的透明窗口。

## 操作与窗口行为

| 操作 | 结果 |
| --- | --- |
| 单击角色或常驻任务气泡 | 按技术设计重新检查服务后打开任务详情；没有可用任务时打开列表 |
| 拖动角色 | 调整位置；移动超过 `4 pt` 后按拖动处理，松开不打开浏览器 |
| 悬停 | 轻微表情反馈并展开信息；移出后收起，进入展开区域时保持可读 |
| 右键或点击菜单栏入口 | 显示同一组菜单 |
| 选择任务 | 用户主动打开面板后才接收键盘输入；确认后关闭面板并立即读取新任务 |
| 隐藏 / 显示 | 隐藏停止动画和轮询；显示恢复当前位置并重新读取 |
| 系统睡眠 / 唤醒 | 停止活动；唤醒后重新读取，首个结果不重放历史提示 |

被动更新、受阻提示和庆祝不激活应用、不抢焦点、不播放声音。拖动时保持抓取点稳定，暂停会改变抓取点
的角色动作；松开后自然进入最新状态，不重放拖动期间已过期的动画事件。

使用 AppKit 常规浮动面板和菜单栏行为。普通桌面上保持可见，切换 Space 时跟随系统支持的窗口行为；
全屏应用采用系统结果，不为特定应用增加侵入式置顶或切换 Space 的实现。原生验收记录实际表现，
且任何情况下用户均可通过菜单栏恢复或退出。

菜单仅包含：

1. 选择任务 / Choose task
2. 选择形象 / Choose appearance（内置、已导入形象与导入入口 / bundled, imported, and import entry）
3. 打开任务列表 / Open task list
4. 重试连接 / Retry connection
5. 动画 / Animations
6. 隐藏或显示 / Hide or Show
7. 退出 / Quit

“重试连接”只在未连接时可用；该显式操作可请求现有 Core 启动本地服务。语言跟随系统偏好：
优先语言为中文时使用简体中文，其余使用英文。动画开关直接位于菜单中，没有独立设置窗口。
系统减少动态效果开启时，菜单说明动画受系统设置限制。

## 完整动画目录

以下保留内置形象的视觉参考目标。导入的用户形象允许单帧，当前功能交付不要求完成这些视觉精修。

以下五类动画全部是交付要求；同一类别内部可以复用骨骼与造型，不能用静态状态图替换整类动画。
普通阶段共享工作主题动作，具体阶段用文字区分，无需为每个 Core 节点创造不同业务含义的动作。

| 素材键 | 动作设计 | 播放规则 | 静态姿态 |
| --- | --- | --- | --- |
| `idle` | 自然呼吸、眨眼、轻微重心转移与偶尔观察；有清晰停顿，避免机械匀速晃动 | 无选择时低干扰循环 | 平静待机 |
| `working` | 专注神态与有节奏的手部/身体动作，装饰有轻微跟随和收势；表现工作主题，不表示 Host 实时运行 | 普通流程阶段循环，节点切换平滑衔接 | 专注姿态 |
| `blocked` | 短暂抬头或疑惑反应，随后进入等待姿态的轻微呼吸、眨眼动作；保留完整动作层次 | 进入受阻或原因改变时提示一次，再使用安静循环；不反复弹跳提醒 | 受阻姿态 |
| `complete` | 预备动作、明确庆祝主体、回落与稳定收势；表情与肢体一致，可有少量随角色消散的装饰粒子 | 只在连续观察到进入 `DONE` 时播放一次，然后静止 | 完成后的满足姿态 |
| `disconnected` | 与任务受阻可区分的失联反应，例如观察连接标记后收回视线，转入轻微等待循环 | 连接失败时进入，停止工作和庆祝动作；持续失联不重复注意力提示 | 未连接姿态 |

`DONE` 首次读取直接显示完成静态姿态；`CANCELLED` 使用平静收势姿态，不借用庆祝动作。
已归档和任务不存在使用中性姿态，并以文案区分。每类动画都必须有专门选择的清晰静态帧，
供关闭动画、系统减少动态效果和首次读取终态时使用。

### 节奏与转场

制作以 `24 fps` 为初始节奏，动作需要时可以提高帧率。主动动作不能用重复帧凑流畅度，停顿则应通过
表演节奏明确表达。待机和普通阶段循环建议 `2–4 s`，受阻/失联的提示段建议 `0.6–1.2 s`，
完成动画建议 `1.8–3 s`；这些是制作参考范围，实际节奏以整段播放质量确定并记录在素材清单。

循环首尾需在位置、轮廓、光照、阴影和速度上自然相接。角色脚底/悬浮参考点固定，不能因逐帧裁切、
画布变化或缩放出现位置抖动。关键动作应有缓入缓出、适量预备动作和收势，避免每个部位同时启停。

必须检查以下转场：待机到普通阶段、普通阶段到受阻、受阻恢复、普通阶段到完成、任意状态断线、
重连恢复，以及动画开关切换。阶段和连接文字立即更新；动作可用短促、自然的姿态衔接或混合过渡，
不等待旧循环播完。不要用全角色长时间淡出再出现掩盖造型不一致。

新任务、新连接或新的终态替换当前画面时，旧庆祝和提示立即取消。首次读取受阻任务直接进入受阻的
安静循环，首次读取 `DONE` 显示静态完成姿态；不播放用户未连续观察到的历史事件。

### 动画关闭与资源控制

用户关闭动画或系统减少动态效果开启时，使用各状态静态帧；文案、选择和跳转仍然正常工作。
重新打开动画只恢复当前允许的循环，不补播完成或受阻提示。隐藏、睡眠和退出停止全部动画计时器。

只解码和保留当前动作及紧邻转场所需的帧。资源控制通过合理画布、缓存释放和按需播放完成，
不得通过删除必需动作、降低成品清晰度或把动作替换成整图晃动来达到。

## 素材交付

源素材放在 `packages/desktop-pet/macos/Assets/`；应用包只装入运行需要的素材。
预览、分镜、源工程与检查录屏保留为实现交付资料，不全部塞入 npm 包。

| 内容 | 要求 |
| --- | --- |
| 角色原稿 | 高分辨率透明源图，保留可编辑源文件或足够精细的原始图层；建议至少 `1024 × 1024 px` |
| 帧序列 | `512 × 512 px` RGBA PNG，相同透明画布、锚点、光源和角色比例；按动作目录连续编号 |
| 五类动作 | `idle/working/blocked/complete/disconnected` 均有完整帧序列、实播预览和指定静态帧 |
| 界面资源 | 菜单栏模板图标、应用图标和气泡装饰与同一角色/品牌一致，缩小后仍清楚 |
| 检查资料 | 棋盘格透明背景预览、浅色/深色/复杂背景预览、关键帧联系表及原生应用录屏 |
| 来源说明 | 记录原创过程、所用源文件和可用授权；进入安装包的字体、图像等资源须可随产品分发 |

`Resources/animations.json` 由内置与导入形象共用，`pet.json` 提供形象身份，详见[形象包设计](appearance-packs.md)：

| 字段 | 内容 |
| --- | --- |
| `canvas` | 统一的 `width`、`height`，均以像素计 |
| `anchor` | 统一参考点 `x`、`y`，用于所有动作对齐 |
| `clips` | 固定五个素材键对应的描述 |
| 每个 clip 的 `frames` | 按播放顺序列出的包内相对 PNG 路径，完整显式清单 |
| `fps` | 该动作的实际播放帧率 |
| `loop_range` | 循环首尾帧索引，含两端；一次性动作使用 `null` |
| `rest_frame` | 静态模式使用的帧索引 |

受阻和未连接动作可将提示段放在循环段之前；首次进入播提示段，保持状态时只循环 `loop_range`。
首次同步或恢复动画时直接进入循环段。完成动作的 `loop_range` 为 `null`，播放结束保持
`rest_frame`。素材清单由构建检查确认五类齐全、文件存在、尺寸一致和索引合法。

Codex 本地宠物包可以在导入时转换为此格式。运行时只使用 Dev Flow 五类展示状态，Codex 任务活动与追视、行走行为不属于素材导入。

## 视觉验收

所有检查同时覆盖中文和英文界面。V06/V07 的执行步骤和结果记录见[验收文档](validation.md)。

| 检查 | 通过条件 |
| --- | --- |
| 造型统一 | 静态原稿、五类动作和界面图标属于同一角色；比例和关键装饰没有逐帧变化 |
| 小尺寸表现 | 在 `96 / 144 / 192 pt` 下能辨识五官、状态姿态和轮廓，正文可读 |
| 透明质量 | 棋盘格、浅色和深色背景下无白边、黑边、残留底色、裁切耳朵或阴影 |
| 循环质量 | 连续观看至少五轮，无首尾跳变、重心漂移、闪帧或不合理停顿 |
| 动作完成度 | 各类动作有独立表演；庆祝有起势与收势，受阻和失联有可区分的反应 |
| 转场质量 | 状态改变时姿态连贯、文字及时；旧任务的动作不会串入新任务 |
| 系统行为 | 不抢焦点、不侵占大面积点击区域；隐藏和减少动态效果立即生效 |
| 成品质量 | 检查原生安装包中的实际画面；仅素材预览或“动画可播放”不足以判定通过 |

先完成角色与关键动作定稿再批量补帧，遇到造型漂移或节奏问题回到对应动作修改。
这些检查用于视觉交付，当前功能交付不以它们通过为前提。
