# Implementation Plan: Bootstrap Monorepo

**Branch**: `001-bootstrap-monorepo` | **Date**: 2026-08-14 |
**Spec**: `specs/001-bootstrap-monorepo/spec.md`

**Input**: Feature specification from `/specs/001-bootstrap-monorepo/spec.md`

## Summary

Create one root Go module, one root pnpm workspace, two private host-product packages, one root Spec
Kit project, one product version source, explicit directory ownership, and bounded repository
validation. The implementation deliberately postpones MCP, SQLite, workflow behavior, host setup,
and publishing.

## Technical Context

**Language/Version**: Go `>=1.26` with `go 1.26` as the language floor; a currently supported Node.js `>=24`; pnpm `>=11 <12`.

**Primary Dependencies**: Go standard library only; no production JavaScript dependencies. The actual supported pnpm 11.x version is selected at execution time and recorded by the lockfile, not asserted as one permanent patch version.

**Storage**: N/A. This feature creates no runtime database or user data.

**Testing**: `go test ./...`; package manifest/dry-pack checks through pnpm; repository-layout and
documentation-link contract tests through bounded repository commands.

**Target Platform**: Development on macOS arm64; pull-request validation on GitHub-hosted Linux.
No end-user platform support claim.

**Project Type**: CLI Monorepo with one Go module and two future npm-distributed host products.

**Performance Goals**: Baseline validation should be suitable for every pull request and must not
perform host launch, release builds, installation, or publication.

**Constraints**: One Spec Kit root; one Go module; private host packages; no runtime behavior; no
release credentials; no global installation; one repository-owned validation entry point.

**Scale/Scope**: A small project skeleton with only the files needed to prove structure, ownership,
version, package, documentation, and CI contracts.
