# Dev Flow 产品定义

[中文](PRODUCT.md) | [English](PRODUCT_en.md)

## 产品定位

Dev Flow 帮助开发者判断一个请求是否需要完整开发流程，并让长时 AI 编程任务的需求、改动范围、验证投入和当前进度在会话中断后仍可继续。

Codex 或 DeepSeek 负责理解代码、修改文件和执行命令。Go Core 保存唯一 Task 状态，观察实际工作树，核对当前结果并决定合法下一步。Task 是一项持久保存的开发任务；Action 是 Core 为当前阶段签发的操作。

## 目标用户与使用场景

产品面向使用 Codex 或 DeepSeek 处理真实代码库、任务可能跨会话或持续多天的开发者。适合涉及公开接口、持久化、多个组件或复杂恢复，以及需要明确文件范围和验证投入的工作。

共享工作区中的其他修改会干扰任务归属；只靠聊天记录难以确认测试是否仍有效、操作是否已经成功，以及中断后还剩什么。Dev Flow 默认在当前目录新建任务分支，也支持当前分支或独立工作树，并保存需求、计划、检查结果、阻塞原因和恢复信息。

一次性问答、代码解释、状态查询和小型机械修改通常直接使用 Host 更简单。一个 Task 可以包含少量显式指定的仓库，但多仓库和工作树交接是高级能力，不代表主要使用场景。

## 创建与恢复任务

新请求先经过只读评估，展示已找到的影响面、未知项和建议。开发者选择直接开发、使用 Dev Flow 或先澄清；显式触发指令也不跳过评估。选择前不创建 Task、不修改 Git、不派发开发会话。

选择 Dev Flow 后，默认在当前目录从当前 HEAD 新建任务分支，也可以明确选择使用当前分支或新建
独立工作树。本地模式复用已有依赖、本地配置及构建目录，在当前会话已获全部目录权限时直接继续。
Host 展示实际目录、当前分支及未提交修改，并取得缺少的目标分支或初始修改选择。被接受的初始修改
全部纳入 Task 范围，保留其暂存状态；不接受时停止准备，不自动清理或排除其他工作的修改。

选择独立工作树时，逐仓确认本地或远端来源、起始分支、新任务分支及本地内容是否携带。本地来源
可以离线准备；远端来源获取指定分支后固定起点。携带选择复制已暂存、未暂存及未被 Git 忽略的新增
内容，保留源目录及暂存状态。任一仓库准备失败都不创建部分 Task，本地分支和修改保留供检查。

同一目录只能有一个活动 Task。Host 在本地分支操作前通过 Core 只读检查已有占用，Core 创建时再
一次取得全部目录的占用。检查不锁住后续 Git 操作，用户和其他工具应避免在准备期间启动另一个写入者。
本地目录中的手工和外部修改也受范围及验证规则检查；Task 期间保持绑定分支。

仓库调查遵循用户指令、适用的仓库规则和 Host 权限。调查可以发现候选仓库，进入 Task 的范围必须先确认，创建后固定。

Codex 启动新会话时保留相关需求讨论和已确定要求，区分未采纳建议与待确定问题。已有且仍有效的选择和授权继续有效；仅对未解决的决定或必需输入询问。

明确恢复已有任务时返回原工作目录实例，从保存的状态继续，不重新创建任务或选择工作树。已确认启动的目标会话核验保存的启动记录后继续初始化。原工作树丢失或被替换时暂停，开发者可以恢复原实例或明确放弃任务。

## 开发前的方案交互

Host 依次展示需求理解与验收条件、设计方案与影响，以及包含任务、预计文件和验证安排的完整计划，并讨论开发者的修改意见。不要求每个阶段各确认一次，但完整计划必须得到明确认可后才能开始实现。选择 Dev Flow 或工作树参数不代表认可尚未展示的方案。

Core 保存待确认计划；等待答复时停留在任务拆分阶段。确认关联当前需求、设计、任务计划的具体内容和计划轮次。内容修订后旧确认失效，恢复会话可以继续阅读同一待确认计划。文件范围优先列具体文件；目录范围应解释覆盖内容和理由。扩大范围后需保存修订计划并再次确认。

Codex 启动助手要求完整影响评估和开发者的流程选择，缺失或存在未解决未知项时拒绝准备工作树。仍有效的选择、明确任务恢复和已确认启动接续保持有效。Host 负责真实展示和接收答复；Core 无法认证对话或拦截完全未调用 Dev Flow 的编辑。

## 改动与验证规则

| 场景 | 当前行为 |
| --- | --- |
| 工作树发生修改 | Core 从绑定目录计算实际改动；本地模式包含手工和外部编辑，独立工作树与源目录后续修改分开 |
| 修改超出计划 | 受支持的结构化工具在写入前询问；其他写入由后续观察发现，未说明路径不能进入测试或交付 |
| 需要处理计划外文件 | 开发者选择单次允许、修改计划或恢复文件；决定由 Core 保存 |
| 分析完成 | 在任务计划中记录检查、理由、初始命令预算、完整套件预期和测试代码预期 |
| 验证额度不足 | 先记录具体的新影响、风险、失败或缺口及必要增加量，再继续测试；已有检查的补做或重跑也可申请额度 |
| 准备完整测试套件 | 每次重新判断定向检查是否足够、尚缺什么检查和当前仓库要求；剩余额度不是扩大测试的理由 |
| 测试精确重复 | 相同失败、相同结果或相同修改与失败循环第三次精确重复后暂停，等待明确处理决定 |
| 修改后复核 | 只检查当前改动、直接或间接影响和验收所需内容；修复后只做相关复查；显式代码审查保持只读并等待单独修复授权 |
| 内容变化 | 使依赖旧内容的测试与理解确认失效；同分支线性提交完全相同内容时保留结果 |
| 工作树历史异常 | 切换分支、分离 HEAD、回退、未准备的历史重写或实例替换会触发阻塞或不可用状态 |

携带的本地内容计入 Task 修改范围。Codex 将内容保留与新开发分别安排工作和检查；保留检查不代表已有业务功能已验证。

Task 创建时不冻结最终验证预算。消耗按当前任务计划统计，正式重建计划后使用新计划预算，旧记录保留。增加额度不产生通过结果，Host 必须报告实际执行的检查及其来源。

## 完成与不确定操作

进入测试前，当前计划全部工作项必须完成。交付逐条关联验收条件、对应的已完成工作和当前通过的检查。自动检查、静态检查、Host 观察和明确人工检查均可使用；开发者理解确认单独保存，不能代替验收检查。

操作结果不确定时，先读取 Core 保存的操作再决定恢复或重试。WebUI 重新打开后仍可发现待恢复提交；Host 交接和工作树准备也依据各自保存的记录处理，避免重复执行。

Codex 先保留完整工具响应，再检查 `ok` 并读取成功结果；明确拒绝按返回的错误和处理指示执行，本地缓存或展示异常不改变原始响应的含义。

全部仓库使用独立工作树时才支持工作区交接。本地模式在原目录恢复。同机交接先由 Core 保存恢复条件，Host 完成一次交接，Core 核对目标后一次替换仓库绑定。失败时保留原绑定与占用记录。

DONE 或 CANCELLED 结束任务并释放仓库占用，不自动提交代码、推送、创建 PR 或删除工作树。本地目录和分支保留，未提交内容会成为下一任务的初始修改。独立工作树和分支的清理分别需要授权；工作树不可用时，明确放弃保存最后已知状态并结束任务。

## 使用入口与组件职责

| 组件 | 用户用途 |
| --- | --- |
| Codex / DeepSeek | 评估请求、执行已确认的开发与 Host 操作，并从同一 Core Task 恢复工作 |
| 统一 lifecycle CLI | 安装、诊断、维护和移除 Adapter，保留普通维护中的 Task 数据与用户配置 |
| 本机 WebUI | 查看任务、结果、阻塞与恢复信息，并通过 Core 提交支持的操作 |
| 桌面宠物 | 显示一个所选 Task 的保存状态并打开对应 WebUI；支持任务选择、自定义形象、动画控制、大小调整与独立启停 |
| OpenSpec / Spec Kit | 可选地组织需求、设计和任务，方法工具的结果不决定 Core 状态 |

桌面宠物由正式 `@imotong/dev-flow` npm 包提供，包含 macOS arm64 与 Windows 10/11 x64 应用和默认素材，运行时需要已配置的 Adapter 提供 Core。维护命令更新应用副本并保留设置与形象。桌面展示不代表 Host 实时活动或完成百分比。安装与素材说明见[桌面宠物指南](DESKTOP-PETS.md)。

## 产品边界

- Core 只读观察 Git；fetch、工作树创建、分支操作、交接和清理由获授权的 Host 执行。
- 工作树隔离源码修改归属，不隔离进程、网络、凭据、端口、数据库、容器或外部服务。
- Core 不拦截 Host 的每次文件操作或 shell 命令；外部写入可能先发生，再由观察检查。
- 产品不自动复制 ignored 文件、安装依赖、扩大仓库范围或清理 active、dirty、未推送、来源不明及结果不确定的资源。
- 不提供通用 Agent、任意 workflow DSL、自定义状态机、跨机器迁移、remote MCP、云端多用户管理或自动 Git 发布。

## 功能决策与已验证范围

功能改进应解决实际任务问题，帮助从正确状态继续，减少开发者判断状态与下一步的工作。决定应基于 Task、Action、仓库观察和保存记录；Core 始终是任务状态的唯一决定者。新增平台、Host 或界面须有具体用户结果与可重复的验收方式。

当前源码能力不等于稳定安装包支持。测试结果只适用于实际验证的产物、平台和步骤；模拟或静态检查不能替代实际 Host 流程。项目尚未通过足够外部数据证明降低缺陷率、验证成本或恢复时间。

稳定支持与未验证范围见[支持矩阵](SUPPORT-MATRIX.md)，当前交付状态和产品缺口见[项目状态](PROJECT-STATUS.md)。协议与实现见[架构说明](ARCHITECTURE.md)，操作参数见[命令参考](COMMANDS.md)。


## Host 交互说明

Codex 与 DeepSeek 的 Core 交互说明和完整示例统一维护于 `skills/dev-flow/core/`，由构建脚本生成各包内的引用文件。各 Host 的授权、工作树准备和工具调用分别说明；实际执行使用当前 Action、已安装接口和真实用户决定。节点提交、返回处理、阻塞恢复与验证规则使用相同内容，并对两边生成的示例运行同一套 Core 校验。
