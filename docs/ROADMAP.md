# Dev Flow 路线图

[中文](ROADMAP.md) | [English](ROADMAP_en.md)

路线图描述尚待改善的用户结果和优先顺序，不承诺日期。已交付能力见[项目状态](PROJECT-STATUS.md)，稳定支持见[支持矩阵](SUPPORT-MATRIX.md)。下列方向需要进一步设计和验证，不是现有功能承诺。

## 优先改善：中断后的理解成本

让开发者恢复任务时，更快看懂已经完成什么、还剩什么、为什么停止和下一步需要谁处理。

- 将现有记录组织成更短、更直接的恢复摘要，突出未完成工作、阻塞原因与可执行的下一步。
- 更清楚地展示哪些检查仍适用于当前代码，以及哪些结果需要重新确认。
- 评估如何保留影响后续工作的失败方案与拒绝原因，减少再次提出已排除方案的情况。
- 评估活动任务收到新增要求时的表达方式，帮助用户区分修改当前任务、安排后续工作与结束当前任务。

新增摘要或记录应复用同一 Core Task，减少理解成本，不能增加另一份流程状态或让 Host 自行判断完成。

## 继续校准：验证与完成判断

- 通过真实使用反馈检查初始验证计划和额度增加是否合适，减少无效测试与误阻塞。
- 改进请求改动量评估的说明和误判反馈，让用户更容易决定是否进入完整流程。
- 提供不确定操作的公开故障注入演示，明确哪些结果已经保存、何时可以恢复。
- 改善完成结果的集中展示，让遗漏的验收项及对应处理方式更容易找到。
- 在保留必要确认与恢复检查的前提下，减少用户需要执行的操作次数。

这些改进应通过实际 Codex 或 DeepSeek 使用场景验证，并区分检查结果、用户反馈和尚未验证的推断。

## 长期候选：协作与任务转移

以下方向优先级低于上述恢复体验和验证判断，需要独立需求与完整设计：

- Codex 与 DeepSeek 之间的任务接管；
- 跨机器 Task 转移及可核验的导出、导入；
- PR / CI 的只读验证摘要与团队只读任务视图；
- 更简单的 OpenSpec / Spec Kit 文档集成。

任务接管与转移必须保留唯一 Core Task 状态、已有结果、未完成工作及授权边界，不能通过复制 Host 阶段来替代。

## 不计划提供的功能

不计划提供通用 Agent、shell 或文件系统安全沙箱、自动 Git 发布、任意 workflow DSL、自定义状态机、自动扫描并加入相邻仓库，以及云端项目管理平台。

新平台、Host 或界面只有在解决明确的长时任务问题、具有可重复验收方式时，才应进入具体实施计划。
