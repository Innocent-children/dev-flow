# 任务经验

[中文](EXPERIENCES.md) | [English](EXPERIENCES_en.md)

## 记录与理解

每次进入 `COMPREHENSION_REVIEW`（理解确认节点），执行当前任务的 AI 都会主动回顾本任务已有的
需求、设计、代码改动、讨论和验证结果，无需用户另外要求“收集经验”。AI 先读取本任务已保存的经验，
再提炼少量有价值的内容，通过 Core 保存后讲解。其他节点不要求主动收集经验。

每条经验说明问题、原因、处理、判断依据、适用条件和下次先检查什么，附带相关项目、阶段、时间和引用，
离开原会话也能读懂。没有值得记录的内容就跳过写入，继续说明实现；不强制数量，也不为经验追加调查、
测试或扩大任务范围。

结论分为 `pending`（待验证）、`supported`（已有依据支持）和 `refuted`（已被推翻）。判断变化时修改
当前内容并说明原因，旧修订继续保存；有价值的排除过程应保留在当前判断依据中。用户补充通过单独操作
追加，后续整理结论会保留这些补充。

保存后，AI 结合经验解释为什么这样处理、适用条件和下次先检查什么。用户可以继续追问，AI 回应已有
材料能够回答的问题，保存真实用户补充；讨论使判断改变时，修订对应经验。返回修改代码后再次进入理解
确认时，重新回顾并更新同一条经验，内容没变就不重复写入。

保存失败时，AI 说明哪些内容尚未保存，保留原请求身份并按 Core 返回的处理方式纠正、回读或重试。
失败不能算作“没有经验”，也不能报告已经保存；未解决时停留在理解确认节点。用户明确确认理解后，才按
原流程进入交付。经验保存或导出成功不能代替理解确认；需要改代码时仍先走当前合法返回路径和验证规则。

自动收集由进入节点后的当前 AI 执行。Core 提供节点要求和持久化，不监听聊天、不生成经验内容，也不调用
另一个模型。这个默认收集时机不限制历史查阅、用户主动补充、修订或手动导出，这些操作沿用已有权限。

## 查找与导出

在本机 WebUI 侧栏打开“任务经验”，按关键词查找。项目筛选接受保存的仓库路径或项目标识；点击经验中的
项目可直接筛选。任务详情中也能阅读经验、查看修订历史、补充理解并导出。归档任务仍参与查找。

任务完成后 Core 自动尝试导出。默认路径为：

```text
macOS:  ~/.dev-flow/data/experiences/<repository-group>/<task-id>.md
Windows: %LOCALAPPDATA%\dev-flow\data\experiences\<repository-group>\<task-id>.md
```

设置 `DEV_FLOW_DATA_DIR` 时，以该目录替换上面的数据目录。导出目录位于任务仓库之外；若自定义配置
会使导出进入任务仓库，Core 保留待导出状态并拒绝写入。目录和任务标识来自 Core，调用方不能指定任意输出路径。

SQLite 保存正式内容，Markdown 是供离线阅读的快照：包含任务背景和状态、最多五条已有依据支持的收获、
完整当前经验、引用及用户补充。历史修订从 WebUI 或 Core 读取。导出不调用模型，不重新推测原因。

没有经验时跳过导出。导出失败不会撤销 `DONE`；任务详情显示失败或待导出状态，点击“导出 Markdown”即可补写。
Host 也可调用 `dev_flow_export_experiences`。重复导出替换同一份完整文件，不追加重复内容。
暂停、受阻、取消及有失败记录的任务也可手动导出，文档如实保留当前状态；本功能不增加独立失败节点。

归档保留数据库经验。现有“永久删除任务”操作同时删除关联经验和导出记录，已导出的 Markdown 留在本地。
工作树清理不会删除数据目录中的经验文件。

## Core 接口

详见[命令参考](COMMANDS.md)和[共享 Host 示例](../skills/dev-flow/core/experience.md)。

| 操作 | 关键输入与结果 |
| --- | --- |
| `dev_flow_save_experience` | `host`、`task_id`、`experience_id`、`request_id`、`expected_revision`、`content`、`change_reason`；新记录 revision 为 0，返回已保存经验 |
| `dev_flow_add_experience_note` | 相同身份字段、经验当前 `expected_revision` 和 `user_note`；追加真实用户补充 |
| `dev_flow_get_experiences` | `host`、`task_id`，可选 `experience_id` 和 `page`；默认当前经验，指定经验 ID 时读取修订历史，同时返回导出状态 |
| `dev_flow_search_experiences` | `host`，可选 `task_id`、`project`、`text`、`page`；包含当前经验、任务状态和归档标记 |
| `dev_flow_export_experiences` | `host`、`task_id`；返回 `generation`、`exported_generation`、`path`、`error` |

写入沿用 Task 的 origin Host 权限；两种 Host 可读取同一历史经验。WebUI 通过同一 Core 服务保存用户补充。
经验 revision 与 Task revision 分开，纯经验写入不改变 Task 快照、Action、节点或任务事件。

首次写入生成并保留稳定的经验 ID 和请求 ID；响应丢失时使用完全相同的请求重试。相同请求 ID 携带不同内容会被拒绝。
修改结论使用新请求 ID 和最新经验 revision；冲突后先读取当前记录。单份编码后的经验修订（含保留的用户补充）
上限为 65536 字节，超限响应报告实际字节数。内容文本单字段上限 8192 字节，标题 240 字节，引用最多 32 条。
读取和查找每页最多 5 条，按 `has_next` 继续；`page` 从 1 开始。

`error` 非空表示导出仍需重试；`generation > exported_generation` 表示保存内容有更新待导出。
成功请求的外层 `ok:true` 不代表文件已导出，必须检查这些字段。导出过程中崩溃后仍可重复补写。

## 限制

经验来自执行任务的 AI 和用户，Core 校验结构和关联关系，不替用户证明每条叙述或外部引用为真。
记录时的内容摘要是历史背景，不赋予当前测试通过或理解确认权限。复用经验前仍需核对适用条件和引用。

本功能只做本地保存、讲解、导出和基础查阅；没有额外模型调用、跨任务推荐、向量检索或学习评分。
经验升级为项目规则或团队规范由用户决定。数据库按项目当前布局策略维护，不提供旧布局迁移。
